# AI 写入操作设计记录

> 状态：后续设计，暂不实现。本文件记录只读 AI Tab 验证后的写入方向，不授权新增写入接口、数据表或小程序交互。

## 1. 首个试点与范围

首个试点限定为“创建地块”。目标是验证 AI 能否协助用户整理表单信息，而不是让 AI 获得任意业务写入权限。

本试点不包含开始种养、记录农事、记录收获、编辑或删除。后续每种写入动作都必须单独评审其字段、权限、确认展示和失败处理，不能因为创建地块已开放就自动复用写权限。

## 2. 核心原则

- 模型只能准备结构化草稿，不能调用现有 `create_plot` Service，也不能直接调用任何写接口。
- 最终写入必须由当前登录用户在小程序中明确确认；确认人仅限当前农场的 OWNER 或 ADMIN。
- 草稿、确认和执行均绑定一个农场。服务端不信任客户端传入的农场、角色、草稿字段或资源 ID。
- 最终执行复用既有 `CreatePlotRequest` 校验和 `create_plot` 业务 Service；AI 不复制或放宽既有业务规则。
- 一次确认只能产生一次写入。重复点击、网络重试和过期草稿不得产生重复地块。
- 写入执行路径需要可追溯，但默认不把完整对话正文或模型原始响应写入审计记录。

## 3. 创建地块流程

```text
用户描述需求
  → 模型通过 prepare_create_plot 整理草稿
  → 缺少名称、类型、面积数值或面积单位时继续追问
  → 服务端创建短时效待确认操作（不创建 Plot）
  → 小程序展示结构化确认卡
  → OWNER / ADMIN 明确确认
  → 服务端再次鉴权、校验草稿、检查幂等键
  → 调用既有 create_plot Service
  → 返回创建结果并记录执行审计
```

用户取消、切换农场、草稿过期或确认失败时，均不写入 `plots`。模型在任意步骤都不能跳过确认卡。

## 4. 草稿与待确认操作

`prepare_create_plot` 是 AI 的业务意图，不是可写工具。它只接受创建地块所需字段，并产生可校验草稿：

- 名称
- 地块类型
- 面积数值
- 面积单位

缺少必填字段、字段无法解析或值不满足既有 Schema 时，模型必须追问；不能自行猜测或补造值。边界坐标等不属于首个 AI 写入试点的字段，仍通过原有地块表单维护。

服务端在生成确认卡前创建短时效的待确认操作。实现时使用新的 Alembic migration，并采用明确的持久化模型，例如：

| 数据 | 最低内容 | 用途 |
| --- | --- | --- |
| 待确认操作 | 操作 ID、动作类型、农场 ID、请求用户 ID、草稿参数、状态、过期时间 | 将一次准备与一次确认绑定；状态至少能区分待确认、已取消、已过期、已执行和执行失败。 |
| 执行审计 | 操作 ID、确认用户 ID、最终参数摘要、结果资源 ID、执行时间、结果状态 | 追溯最终写入，不保存完整消息正文或模型原始输出。 |

具体表名、字段类型和保留期限在 A4 规格中确定；此处不预先建立通用工作流表或多动作抽象。

## 5. 确认与执行边界

确认接口应接收一次性操作 ID 与客户端生成的幂等键。单个数据库事务中至少完成：

1. 读取待确认操作，并校验其仍属于当前农场、未过期且状态允许执行。
2. 用当前 JWT 用户重新校验 FarmMember 身份和 OWNER / ADMIN 角色。
3. 用保存的草稿重新构造并校验 `CreatePlotRequest`。
4. 使用既有 `create_plot` Service 创建地块。
5. 将待确认操作标记为已执行，写入审计结果，并将幂等键与执行结果关联。

任一步失败都不得把操作错误地标为已执行。相同幂等键的重试应返回第一次的最终结果，而不是再次创建地块。草稿过期、角色变化或当前农场不一致时必须拒绝确认。

## 6. 小程序交互

AI 回答中不嵌入可执行链接或自由文本指令。准备完成后，页面以原生结构化确认卡展示：当前农场、名称、类型、面积和单位，以及“取消”和“确认创建”两个操作。

确认前用户应能回到对话继续补充或修改信息；修改后必须生成新的草稿，旧草稿不能被复用。确认成功后显示实际创建结果并跳转或提供进入地块详情的入口。失败时保留可理解的错误状态，不假定创建成功。

## 7. 最低测试边界

- MEMBER 无法确认创建；OWNER 与 ADMIN 可以确认自己当前农场内的草稿。
- 非成员、切换农场后的用户以及角色被降级的用户无法确认。
- 缺失字段、非法面积、非法单位和非法地块类型不会生成可执行草稿。
- 取消、过期、二次确认、并发确认和相同幂等键重试都最多创建一个地块。
- AI 准备草稿的任意失败路径不会写入 `plots`。
- 审计记录不包含 JWT、手机号、模型密钥、完整对话正文或完整模型原始响应。

## 8. 后续扩展

“开始种养”“记录农事”“记录收获”可沿用“准备 → 明确确认 → 二次鉴权 → 幂等执行 → 审计”的安全边界，但必须分别设计草稿字段、可确认角色、状态条件和失败恢复方式。

在只有少量独立确认动作时，普通业务状态表和显式 Service 流程足够，不引入 LangChain 或 LangGraph。只有多个已验证写入动作需要跨请求恢复、并行编排或复杂人工审批时，才重新评估工作流框架。
