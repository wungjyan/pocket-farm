# 收获记录与农事记录页面评审

## 1. 评审范围

本次只记录现状、问题和待确认方向，不包含开发方案落地。

- 收获记录列表：`apps/miniapp/src/pages/harvests/index.vue`
- 收获记录表单：`apps/miniapp/src/pages/harvests/form.vue`
- 农事记录列表：`apps/miniapp/src/pages/operations/index.vue`
- 农事记录表单：`apps/miniapp/src/pages/operations/form.vue`

## 2. 当前实现关系

“收获记录”和“农事记录”没有共用页面，是两套独立实现。

收获记录内部存在复用：农业、林业、牧业和渔业都使用 `pages/harvests/index.vue`，再根据种养行业显示“采收”“出栏”或“捕捞”。该页面同时支持以下两个入口：

- 传入 `productionId`：查看某个种养批次的收获记录。
- 传入 `plotId`：查看整个地块下不同种养批次的收获记录。

农事记录使用 `pages/operations/index.vue`，当前只支持按 `plotId` 查看地块农事记录。

## 3. 重复实现

虽然不是共用页面，但两套代码重复实现了相似职责：

- 加载地块、种养、农场成员和记录列表。
- 格式化记录时间、操作人和记录人。
- 根据关联种养是否进行中判断记录能否修改。
- 列表卡片、加载态、失败态、空状态和删除确认。
- 点击可编辑记录直接进入表单；已锁定记录点击后无响应。
- 编辑表单通过记录列表反查目标记录，而不是按记录 ID 读取单条数据。

目前不建议仅为了消除重复而直接合并成一个页面。两类记录的核心字段、创建入口和业务行为不同，应先确定交互，再判断是抽取通用列表壳、状态组件和格式化方法，还是继续保持独立页面。

## 4. “已锁定”状态逻辑

### 4.1 收获记录

收获记录一定关联种养批次。当关联种养状态不是 `ACTIVE` 时，前端将记录标记为“已锁定”。后端同样禁止对已结束种养的收获记录执行新增、修改和删除。

### 4.2 农事记录

农事记录可以关联种养，也可以只关联整个地块：

- 关联种养且该种养已结束：记录被标记为“已锁定”，后端禁止修改和删除。
- 只关联整个地块：`productionId` 为空，不受种养结束状态影响，仍可修改和删除。

### 4.3 为什么不能进入详情

当前两套列表都没有只读详情页。列表项点击行为直接绑定“进入编辑表单”，代码检测到记录已锁定后直接返回，因此用户看到的是点击无响应。

这不是后端禁止读取历史数据，而是前端把“查看”和“编辑”合并为同一个入口后产生的交互缺口。

## 5. 当前主要问题

### 5.1 交互问题

1. “已锁定”表达的是不可修改，但页面表现成不可查看，含义不一致。
2. 已锁定卡片仍呈现为可点击卡片，点击却无反馈，容易被理解为页面失效。
3. 未锁定卡片点击直接编辑，缺少稳定的查看层；用户无法在不进入编辑状态的情况下阅读完整备注等信息。
4. 删除按钮直接放在列表项右侧，浏览与高风险操作混在一起，且点击区域与整卡编辑入口相邻。

### 5.2 数据读取问题

1. 后端已有带成员权限校验的单条记录查询服务，但没有对前端开放对应的单条读取接口。
2. 两个编辑表单都是先取最多 100 条列表，再在前端按 ID 查找目标记录。记录超过 100 条时，存在记录实际存在但表单提示不存在的风险。
3. 地块列表一次最多读取 100 条，没有翻页或继续加载；页面显示的条数使用当前数组长度，可能不等于接口返回的真实总数。

### 5.3 页面结构和样式问题

1. 导航栏已经显示页面名称，页面内部又显示一次大标题，首屏垂直空间利用率偏低。
2. 列表项同时使用左侧业务图标、收获色边线、状态标签、锁图标或删除图标，视觉元素偏多，正文信息层级被削弱。
3. 单项内部横向空间被图标和操作按钮占用，标题、数量、种养名称及操作人更容易拥挤。
4. 卡片外间距和内部行距缺少统一节奏；元信息行间距偏紧，而卡片整体高度主要由左右装饰元素撑开。
5. 收获记录和农事记录的页面头部、状态表现和列表密度相近但不一致，用户在两个页面间切换时会感到跳变。

## 6. 建议后续先确认的方向

### 优先级 P0：确定查看与编辑关系

- 历史记录是否都应允许查看完整详情。
- 进行中的记录是点击列表直接编辑，还是统一先进入详情再编辑。
- 删除操作放在列表、详情页，还是编辑页。

### 优先级 P1：统一状态语义

- 将“已锁定”明确为只读状态，而不是不可点击状态。
- 进行中与已结束记录保持相同的信息展示，仅在可用操作上区分。
- 如果暂不开发详情页，至少需要为已锁定卡片提供明确反馈，避免静默无响应。

### 优先级 P1：修正单条读取与分页

- 为收获记录和农事记录提供按 ID 读取的接口，并继续沿用 FarmMember 权限校验。
- 编辑表单按 ID 获取目标记录，不再依赖前 100 条列表。
- 明确地块记录列表采用分页、触底加载还是固定数量展示，并使用接口 `total` 作为真实总数。

### 优先级 P2：统一列表视觉规范

- 保留独立卡片，但减少列表项装饰元素，优先展示业务标题和两至三行关键信息。
- 统一页面左右边距、卡片间距、卡片内边距、标题与元信息行距。
- 导航入口统一使用行尾箭头；删除等危险操作不与主要浏览入口并列。
- 两类页面共享视觉规则，但不提前强制合并业务组件。

### 优先级 P2：评估可复用范围

在交互方案确定后，再评估抽取以下低风险能力：

- 日期、成员名称和记录人文本格式化。
- 加载、失败和空状态组件。
- 记录列表的页面工具栏与卡片基础布局。

不建议当前直接把收获记录和农事记录合并为一个带大量条件分支的通用页面。

## 7. 已确认的第一步范围

第一步只处理两个列表页面的 UI 样式，范围如下：

- 删除列表项左侧业务图标和收获卡片左侧强调边线。
- 使用统一页面留白、紧凑工具栏、独立卡片间距、卡片内边距及文本层级。
- 保留当前不可变更判断、创建、编辑和删除行为，状态文案改为“种养已结束”。
- 不新增详情页和单条读取接口，不处理历史种养名称、超过 100 条时的分页与总数问题。

## 8. 已确认的第二步范围

- 农事记录新增单条读取接口和统一详情页。
- 所有农事列表项进入详情；可变更记录在详情中编辑、删除，关联种养已结束的记录仅展示详情。
- 列表顶部明确显示地块名称与农事记录数量，并高亮实际值。
- 收获记录的详情、不可变更交互和单条读取在第三步处理；分页问题仍不在当前范围。

## 9. 已确认的第三步范围

- 收获记录新增单条读取接口和统一详情页。
- 所有收获列表项进入详情；可变更记录在详情中编辑、删除，关联种养已结束的记录仅展示详情。
- 列表顶部按入口明确显示种养或地块名称与收获记录数量，并高亮实际值。
- 保留现有分页上限与列表数据口径，不合并农事、收获页面实现。
