## 3. 视觉基线入口

全局视觉与交互规则统一维护在《[小程序 UI 设计规范](./01-miniapp-ui-design-guidelines.md)》。本节只保留当前重构计划中的业务数据口径；页面级特殊设计继续记录在各 R 项中。若旧描述与 UI 设计规范冲突，以 UI 设计规范为准。

### 3.1 农场概览

- “全部地块”包含闲置地块，展示地块数与总面积。
- “闲置地块”指没有 ACTIVE Production 的地块，展示闲置地块数与闲置总面积。
- 地块面积改为必填前，缺失面积按 `0` 汇总。
- 两组数据使用等权重的白底浅阴影卡片，点击均进入当前农场地块列表。

### 3.2 当前种养

- 标题右侧按 `speciesId` 去重显示“共 x 种”。
- 同一种类存在多条 ACTIVE Production 时，列表仍逐条展示。
- 行内不显示行业图标和重复的“进行中”状态。

## 4. R5：农场概览地块筛选列表

### 4.1 目标

为农场 Tab 的“全部地块”和“闲置地块”概览卡提供独立的摘要列表页面；不修改首页“地块管理”和既有地块管理／选择页面。

### 4.2 交互与数据口径

- 默认筛选为“全部种类”，展示当前农场全部地块。
- 筛选器使用小程序原生 `picker mode="selector"`，选项为“全部种类”、当前 ACTIVE 种养种类（按 `speciesId` 去重）；仅当前农场确有空闲地块时才追加“空闲地块”。
- “空闲地块”指没有 ACTIVE Production 的地块。
- 一个地块存在多个 ACTIVE Production 时，可以同时命中多个种类筛选。
- 从“全部地块”卡进入时携带全部筛选，从“闲置地块”卡进入时携带空闲筛选。
- 列表行展示地块名称、类型、面积、当前种养标签，点击后进入既有地块详情页。
- 每个地块作为独立的白底浅阴影卡片展示，卡片之间使用间距区分，不使用一个外层列表卡片包裹多个地块。
- 截图中的地图、搜索、地块分组、悬浮新增按钮和作物图片不属于本次范围。

### 4.3 实现范围

- 新增 `pages/farm-plots/index` 页面和路由。
- 使用农场级分页地块摘要接口获取地块及进行中种养种类，另通过农场级筛选元数据接口获取筛选选项；不在前端逐地块查询进行中种养。
- 保留 `/pages/plots/index` 的管理／选择模式及其所有既有调用方。

### 4.4 验收

- 全部地块、闲置地块两个入口分别带入正确初始筛选。
- 无 ACTIVE Production 的地块只出现在“全部种类”和“空闲地块”结果中。
- 多种养地块能在对应多个种类筛选中出现。
- 无结果时显示空状态，可返回全部地块。
- 农场切换后重新加载当前农场数据，不展示旧农场列表。
- 通过前端 TypeScript 检查和微信小程序构建。

- 种养表单固定展示已选种类和品种，用户返回上一步修改；地块、日期、种植标准、数量和备注等字段保持不变。
- 从地块详情进入时携带 `plotId` 并预选地块；从首页和农场 Tab 进入时仍由表单选择地块。

### 5.3 验收

- 品种为空或有值时均可进入种养表单。
- 种养表单中种类和品种不可直接修改，返回上一步后可修改。
- 创建成功后返回原始入口页面，不回到首页。

## 6. R4：农场级生产记录页

### 6.1 目标

提供当前农场范围内的生产记录查询入口。页面使用三个顶层 Tab：种养、农事、收获；本期只实现“种养”Tab，“农事”和“收获”仅占位。

### 6.2 页面结构

页面标题为“生产记录”，顶部为三个顶层 Tab：

```text
种养    农事    收获
```

- “种养”Tab 展示当前农场种养记录，筛选默认值为行业=全部行业、状态=进行中。
- 筛选使用两个原生 `picker`：作物大类（全部行业／农业／林业／牧业／渔业）与种植状态（进行中／已结束／全部状态）；切换筛选后重置分页重新加载。
- 列表行展示种类名、品种标签、所属地块、开始日期；进行中记录附初始数量（`formatNumber`），已结束记录显示结束日期、文字置灰并附灰色“已结束”标签。点击行进入既有种养详情页。
- “农事”“收获”Tab 可切换，面板内分别显示“农事记录待上线”“收获记录待上线”占位提示，不伪造数据、不发起请求。

### 6.3 后端实现

不使用原计划的统一 `records` 混合时间线接口：改为 Tab 分栏后，各记录类型独立查询，本期新增农场级种养分页接口：

```text
GET /api/v1/farms/{farmId}/productions?industry=&status=&page=1&pageSize=20
```

接口要求：

- `industry` 支持 `AGRICULTURE`、`FORESTRY`、`LIVESTOCK`、`FISHERY`，缺省不过滤；`status` 支持 `ACTIVE`、`ENDED`，缺省不过滤；分页默认 `page=1`、`pageSize=20`，最大 `pageSize=100`。
- 返回轻量 Response DTO（含 `plotName`、`plotAreaValue`、`plotAreaUnit`、种类、行业、个体单位、品种、状态、起止日期与初始数量），不直接返回 SQLAlchemy Model。
- 排序沿用 Production 口径：ACTIVE 优先、同状态按 `startedOn DESC`；筛选、计数和分页均在数据库完成。
- 所有查询检查当前用户的 FarmMember 权限；未加入农场的用户返回 404。
- 不引入新的基础设施或事件总线，无数据库结构变更。

### 6.4 前端实现

- 新增 `pages/records/index` 页面与路由；农场 Tab 的“生产记录”入口改为跳转该页，不再提示“生产记录待完成”。
- 进入页面时携带当前 `farmId`，跟随当前农场上下文；农场切换后重新加载，不展示旧农场记录。
- 复用现有 token、`PfBusinessIcon`、`PfRowChevron` 与空状态样式；业务数值统一使用 `formatNumber`。
- 种养列表中的地块按“地块名（面积）”展示；面积缺失时仅展示地块名，与农事列表保持相同口径。

### 6.5 测试与验收

- OWNER、ADMIN、MEMBER 均可查看已加入农场的种养记录；未加入农场的用户不能访问（404）。
- 行业与状态的单独及组合筛选、总数、分页和排序正确。
- 一个地块多条 ACTIVE Production 与已结束种养均能正确展示。
- 农场切换、空状态、加载失败状态正确；“农事”“收获”Tab 占位不发起请求。
- 后端通过 pytest、Ruff 与 Alembic 检查；前端通过 TypeScript 检查和微信小程序构建。

## 11. R10：业务入口图标资源统一（Lucide）

### 11.1 范围与排除项

本项只统一带浅色背景容器的业务图标，例如首页快捷入口、最近动态、农场入口和“我的”菜单图标。

地块详情的快捷操作虽然沿用无背景分段布局，但其中的业务图标也只替换资源，不改变该页面的布局表现。

- 不修改现有 `uv-icon` 的箭头、表单、选择器、提示、错误状态和其他非业务图标；地块类型区分图标按本项要求移除。
- 不修改原生 TabBar 图标；TabBar 已使用 Lucide 资源。
- 不使用图标区分地块类型，地块类型继续使用文字信息。
- 本轮不处理行尾箭头；箭头仍按 R3 计划后续统一。

### 11.2 资源来源与处理规格

- 图标集统一使用 [Lucide 官方图标](https://lucide.dev/icons/categories)，通过 [Iconify Lucide](https://icon-sets.iconify.design/lucide/) 获取 SVG 后统一栅格化。
- SVG 只作为处理过程中的临时源文件，不进入小程序资源目录；小程序最终只保留 PNG。
