# 小程序页面架构与视觉基线

## 1. 文档定位

本文是“掌上农场”小程序的页面和视觉设计基线，服务于后续前端实现。

当前状态：

- 后端已完成 Phase 3：Plot；下一阶段为 Phase 4：Species + Production。
- 小程序已完成首批基础壳层、Phase 2 农场管理页面和 Phase 3 地块列表、创建、详情、编辑页面；首页的种养、农事和收获聚合内容仍按后续 Phase 接入。
- 三个 Tab 已使用小程序自定义头部，并适配状态栏和胶囊按钮区域；登录页、昵称编辑页继续使用原生导航栏。
- 本文确定信息架构、页面职责、交互规则和主题样式；已实现的首批壳层仅代表视觉与导航基线，不代表后续业务页面已经完成。
- 后续页面实现必须继续遵守 `00-project-overview.md`、`02-domain-model.md` 和 `03-business-rules.md`。

删除农场不属于当前 MVP 范围。后续“农场管理”页面不提供删除农场入口；如果未来增加删除能力，需单独定义数据保留、关联数据处理和恢复规则。

## 2. 一级信息架构

TabBar 只保留三个一级入口：

```text
首页
农场
我的
```

| Tab | 定位 | 主要回答的问题 | 不负责的内容 |
| --- | --- | --- | --- |
| 首页 | 当前农场的工作台 | 我现在有什么需要关注和操作？ | 完整历史查询、成员管理 |
| 农场 | 当前农场的生产现场 | 当前农场有哪些地块，正在发生什么？ | 农场设置、角色权限、成员管理 |
| 我的 | 用户账号与农场管理 | 我是谁，我有哪些农场，如何管理？ | 日常生产记录 |

地块是生产信息的聚合中心，Production 是一次种养生命周期的中心。用户界面不展示 `Production`、生产批次、种植计划等内部术语。

以下页面是独立二级业务页面，不作为 TabBar：

```text
开始种养

结束种养
选择种类
选择地块
选择种养
```

## 4. 当前农场上下文

当前农场是全局工作上下文。首页和农场 Tab 的自定义导航栏居中展示当前农场名称，不提供切换操作，也不显示下拉箭头或 chevron，避免造成可点击误导。名称过长时单行省略。

唯一的农场切换入口是：

```text
我的 → 我的农场
```

前端使用共享的 `selectedFarmId`（连同必要的名称快照）持久化当前选择。交互规则：

1. 登录后恢复上次选择的农场。
2. 在成功获取当前用户可访问的农场列表后，校验已保存的农场是否仍有效。
3. 如果已保存的农场失效、被移除或删除，切换到列表中的第一个有效农场；列表为空则清除当前农场并引导创建。
4. 在“我的农场”选择新农场后，返回页面并刷新首页、农场 Tab 及后续业务页面的数据。
5. 用户没有任何农场时，首页、农场和“我的农场”各自只展示一个明确的创建引导，不重复堆叠空状态。

## 5. 首页

首页是用户打开小程序后的默认工作台，只展示当前农场的少量关键内容。

### 5.1 数据概览

第一版只展示最核心的统计：

```text
12        8
地块      进行中种养
```

暂不增加今日农事、今日采收、累计产量、作物数量、成员数量等大量统计卡片。

### 5.2 当前种养

展示当前农场最近的 3～5 条 ACTIVE 种养：

```text
黄瓜
1 号大棚
8 月 1 日开始 · 已种植 17 天
```

点击进入对应的地块详情或种养详情。底部提供“查看全部种养”。

### 5.3 最近动态

农事、采收、捕捞和出栏统一展示为最近动态，不拆成多个大模块：

```text
今天 14:20
1 号大棚 · 黄瓜
施肥 · 张三

昨天 17:30
东鱼塘 · 鲈鱼
捕捞 35 kg · 李四
```

这里只负责回答“最近发生了什么”，不替代地块历史列表。

### 5.4 快捷操作

首页提供：

```text
开始种养    记农事    收获
```

“收获”根据行业显示为“采收”“捕捞”或“出栏”。如果尚未确定具体 Production，先进入选择地块和种养的流程。

## 6. 农场 Tab

农场 Tab 代表当前农场的生产空间，主体是地块，而不是农场管理。

### 6.1 地块列表

顶部显示当前农场名称及少量辅助数据，例如：

```text
当前农场
开心农场
12 个地块 · 8 个正在种养
```

地块卡片只展示摘要，不塞入所有 Production 字段：

```text
1 号大棚
大棚 · 6.3 亩

黄瓜
种植第 17 天
```

空闲地块：

```text
2 号田
大田 · 12 亩

当前空闲
```

一个地块存在多个 ACTIVE Production 时，只显示代表性摘要和“2 个种养中”，完整内容在地块详情查看。

### 6.2 全部种养

这是独立二级页面，不增加第四个 Tab。入口来自首页“查看全部种养”或农场 Tab 的进行中种养入口。

页面使用两个筛选：

```text
[进行中] [已结束]
```

列表必须同时展示种类、地块和开始／结束时间，用于跨地块查看当前和历史种养。

### 6.3 农场 Tab 的管理入口

首版不在农场 Tab 放置成员管理主入口。若确实需要快捷入口，可在顶部更多菜单提供“农场信息”；成员管理的正式入口固定为：

```text
我的 → 我的农场 → 某个农场 → 成员管理
```

## 7. 地块详情

地块详情是 MVP 最重要的业务页面，是地块基本信息、当前种养、历史种养、农事和收获的聚合中心。

顶部展示：

```text
1 号大棚
大棚 · 6.3 亩
```

地图或地块轮廓是可选增强内容，不得阻塞地块创建和生产记录。没有边界数据时仍然显示普通信息卡。

主要操作：

```text
开始种养    记农事
```

存在 ACTIVE Production 时，在对应种养卡片上提供“采收／捕捞／出栏”和“结束种养”。

地块详情固定使用：

```text
种养 | 农事 | 收获
```

### 7.1 种养

当前种养优先展示：

```text
黄瓜
品种：水果黄瓜

8 月 1 日开始
已种植 17 天

普通 · 移栽 · 人工

[采收] [结束种植]
```

一个地块存在多个 ACTIVE Production 时分别展示，不假设一个地块只能有一条当前种养。历史种养进入列表或折叠区域。

### 7.2 农事

展示该 Plot 的全部 FarmOperation，包括：

- 关联某个 Production 的农事
- `productionId = null` 的纯地块农事

提供“+ 记农事”入口。

操作人和记录人遵循以下规则：

- 操作人默认当前登录用户，但允许选择当前农场的其他有效成员。
- 记录人由后端从 JWT 自动写入，前端不提供编辑入口。
- 如果操作人与记录人相同，可以只展示“操作人”。
- 如果二者不同，同时展示“操作人”和“记录人”。

### 7.3 收获

展示该地块下所有 Production 的 HarvestRecord，并标识其所属种养：

```text
08-17
黄瓜 · 1 号大棚
采收 80 kg
操作人：李四 · 记录人：张三
```

## 8. 我的 Tab

我的 Tab 负责用户账号和低频农场管理。

首页建议展示：

```text
头像
昵称
138****8888

我的农场       >
个人资料       >
关于掌上农场   >

退出登录
```

当前 MVP 只实现用户昵称修改，不提供手机号修改、密码、微信登录或空的“设置”页面。

### 8.1 我的农场

展示用户加入的全部 Farm：

```text
开心农场
农场主 · 12 个地块
>

生态农场
管理员 · 8 个地块
>

鱼塘基地
成员 · 3 个地块
>

+ 创建农场
```

MVP 暂不提供“加入农场”流程。加入能力需要后续单独设计 farmCode 搜索、申请和审批。

### 8.2 农场管理

从“我的 → 我的农场 → 某个农场”进入，根据 FarmMember 角色展示能力：

| 角色 | 页面能力 |
| --- | --- |
| OWNER | 农场信息、成员管理、农场编号、退出农场 |
| ADMIN | 农场信息、成员管理、退出农场 |
| MEMBER | 农场信息、退出农场 |

删除农场不在 MVP 页面和接口范围内。OWNER 退出仍须遵守“农场至少保留一位 OWNER”的业务规则。

### 8.3 成员管理

成员列表展示昵称和角色，不展示完整手机号：

```text
张三
农场主

李四
管理员

王五
成员
```

权限规则沿用业务文档：ADMIN 不能操作 OWNER，OWNER 至少保留一位；前端按钮状态不能代替后端权限校验。

## 9. 独立业务页面

### 9.1 开始种养

流程：

```text
选择种类 → 填写种养信息 → 提交
```

从地块详情进入时自动带入 Plot；从首页快捷入口进入时需要选择 Plot。根据 Industry 显示农业／林业、牧业、渔业对应字段。

### 9.2 选择种类

Species 使用独立选择页面，不用一个普通 Picker 承载大量选项：

```text
选择种类

[搜索种类]

最近使用
黄瓜  水稻  鲈鱼

农业   林业   牧业   渔业
```

Species 为系统预置数据，前端不提供管理入口。

### 9.3 记录农事

从地块详情进入时自动带入 Plot。Production 选择规则：

| 地块状态 | 默认行为 | 请求中的 `productionId` |
| --- | --- | --- |
| 没有 ACTIVE Production | 整个地块 | `null` |
| 只有一条 ACTIVE Production | 自动选中 | 该 Production ID |
| 多条 ACTIVE Production | 用户选择某次种养或整个地块 | 对应 ID 或 `null` |

表单默认当前时间、当前用户和人工作业方式。操作人可以改选当前农场成员；记录人不由前端传入。

### 9.4 记录收获

从具体 Production 进入时自动带入 Plot、Species 和 Production。页面标题根据 Industry 显示“采收”“捕捞”或“出栏”。

核心字段：

```text
数量、单位、作业方式、时间、操作人、产品名称、产品等级、备注
```

默认人工、当前时间和当前登录用户为操作人；操作人允许修改，记录人由后端生成。

### 9.5 结束种养

页面保持简单，只填写结束日期并确认：

```text
结束种植

黄瓜
1 号大棚

结束日期
2026-08-17

[确认结束]
```

允许没有任何 HarvestRecord 的 Production 直接结束，不要求重复填写产量、原因或备注。

## 10. 视觉主题基线

### 10.1 设计定位

主题定位为：自然、可靠、轻量、易操作的生产管理工具。

避免过度卡通化、复杂渐变和高饱和装饰，让颜色承担行业状态提示，而不是装饰页面。

### 10.2 颜色 Token

正式 Token 使用以下命名，前端实现时保持变量名一致：

```css
:root {
  /* Brand */
  --primary: #2f7d4a;
  --primary-pressed: #276a3e;
  --primary-light: #eaf4ec;
  --primary-subtle: #f3f8f4;

  /* Background */
  --bg-page: #f7f8f3;
  --bg-card: #ffffff;
  --bg-muted: #f3f5f1;

  /* Text */
  --text-primary: #202821;
  --text-secondary: #667068;
  --text-tertiary: #929a93;
  --text-inverse: #ffffff;

  /* Border */
  --border: #e2e6e0;
  --divider: #ecefeb;

  /* Harvest */
  --harvest: #d79532;
  --harvest-light: #fbf3e5;

  /* Aquaculture */
  --water: #4c91a0;
  --water-light: #eaf4f5;

  /* Danger */
  --danger: #c95d52;
  --danger-light: #fbefee;

  /* Warning */
  --warning: #c7862b;
  --warning-light: #fbf3e4;
}
```

语义约定：

| Token 组 | 用途 |
| --- | --- |
| `primary` | 主按钮、选中 Tab、主要链接和确认操作 |
| `primary-light` / `primary-subtle` | 选中背景、成功提示、轻量品牌背景 |
| `bg-*` | 页面、卡片和弱化区域背景 |
| `text-*` | 标题、正文、辅助信息和反色文字 |
| `border` / `divider` | 控件边框、卡片边界和内容分隔 |
| `harvest` | 采收、成熟、产量等农业生产状态 |
| `water` | 鱼塘、渔业和灌溉等水产语义 |
| `danger` | 错误、移除和危险操作 |
| `warning` | 风险提醒、待处理和非阻断性警告 |

`harvest`、`water` 和 `warning` 主要用于图标、标签、边框和浅色背景，不直接作为普通小字号正文颜色。`text-tertiary` 只用于占位符、禁用态或非关键信息。危险操作优先使用 `danger-light` 搭配深色文字；如果未来需要使用实心危险按钮，应另行补充满足对比度要求的深色危险 Token。

### 10.3 组件风格

- 页面背景使用 `--bg-page`，内容卡片使用 `--bg-card`。
- 卡片圆角建议 12～16 px，按钮和标签采用适度圆角。
- 使用线性、圆润、易识别的图标；TabBar 图标保持同一套线宽。
- 主操作使用叶绿色；危险操作使用红色，并要求二次确认。
- 农业、林业、牧业、渔业可使用辅助色区分，但不改变主品牌色。
- 默认使用系统中文字体，不为 MVP 引入额外字体资源。
- 首版只做浅色主题，不增加暗色模式和复杂动效。

## 11. 实现边界与顺序

页面规划可以先完成，但页面实现仍按开发计划推进：

1. Phase 2～7 先逐步提供 Farm、Plot、Species、Production、FarmOperation 和 HarvestRecord 接口。
2. Phase 8 实现地块详情的聚合接口和页面。
3. Phase 9 进行完整小程序联调，覆盖首页、农场、我的及核心业务流程。

首页的概览、最近动态和跨资源聚合属于聚合展示能力，不在当前 Farm/Plot 阶段提前实现。

本文不新增数据库表、接口或前端代码。
