# 小程序页面架构与视觉基线

## 1. 文档定位

本文是“掌上农场”小程序的页面和视觉设计基线，服务于后续前端实现。

当前状态：

- 后端和小程序已完成 Phase 9：小程序完整联调；MVP 计划内阶段均已完成。
- 小程序已完成首批基础壳层、农场管理、独立地块列表与管理、种类选择、种养、农事和收获记录页面；首页作为全局工作台，承载核心生产入口、当前农场简要状态和统一最近动态。
- 三个 Tab 使用左对齐单行标题的固定自定义头部，并适配状态栏和胶囊按钮区域；首页和农场显示当前农场名称，“我的”显示页面名称。除非单独说明，所有二级页面统一使用微信原生导航栏。
- 本文确定信息架构、页面职责、交互规则和主题样式；已实现的首批壳层仅代表视觉与导航基线，不代表后续业务页面已经完成。
- 后续页面实现必须继续遵守 `00-project-overview.md`、`02-domain-model.md` 和 `03-business-rules.md`。

删除农场不属于当前 MVP 范围。后续“农场管理”页面不提供删除农场入口；如果未来增加删除能力，需单独定义数据保留、关联数据处理和恢复规则。

## 2. 一级信息架构

TabBar 只保留三个一级入口：

```text
首页
农场
我的
```

| Tab | 定位 | 主要回答的问题 | 不负责的内容 |
| --- | --- | --- | --- |
| 首页 | 全局生产工作台 | 我现在可以做什么，最近发生了什么？ | 当前种养清单、完整历史查询、成员管理 |
| 农场 | 当前农场总览 | 当前农场的规模和生产状态如何？ | 逐条罗列全部地块、角色权限管理 |
| 我的 | 用户账号与农场管理 | 我是谁，我有哪些农场，如何管理？ | 日常生产记录 |

地块是生产信息的聚合中心，Production 是一次种养生命周期的中心。用户界面不展示 `Production`、生产批次、种植计划等内部术语。

## 4. 当前农场上下文

当前农场是全局工作上下文。首页和农场 Tab 的固定自定义头部统一只显示当前农场名称，不再使用“工作台”“农场总览”等页面说明；TabBar 的选中状态负责表达当前页面。我的 Tab 仍显示“我的”。头部不提供农场切换，也不显示下拉箭头或 chevron，避免造成可点击误导。名称过长时单行省略，没有当前农场时显示“未选择农场”。

### 4.1 导航栏规则

- 首页、农场、我的三个 Tab 保留自定义导航头，以便页面背景和身份信息连续展示。头部固定在窗口顶部，页面使用等高占位避免内容被遮挡，滚动时头部不移动。
- 登录页和全部二级页面默认使用微信原生导航栏，依赖系统提供固定定位、返回行为和胶囊安全区，不在页面内容内重复绘制标题或返回按钮。
- 同一路由承担不同模式时，通过 `setNavigationBarTitle` 更新原生标题，例如地块页面在管理模式显示“地块列表”，在表单选择模式显示“选择地块”。
- 只有明确记录了沉浸式、地图或其他特殊导航需求的页面，才允许使用二级页自定义导航；新增例外前必须先确认需求。
- 编辑表单切换为原生导航后，使用微信的离开页面确认能力保护未保存内容，不为拦截返回而重新绘制导航栏。

唯一的农场切换入口是：

```text
我的 → 我的农场
```

前端使用共享的 `selectedFarmId`（连同必要的名称快照）持久化当前选择。交互规则：

1. 登录后恢复上次选择的农场。
2. 在成功获取当前用户可访问的农场列表后，校验已保存的农场是否仍有效。
3. 如果已保存的农场失效、被移除或删除，切换到列表中的第一个有效农场；列表为空则清除当前农场并引导创建。
4. 在“我的农场”选择新农场后，返回页面并刷新首页、农场 Tab 及后续业务页面的数据。
5. 用户没有任何农场时，首页、农场和“我的农场”各自只展示一个明确的创建引导，不重复堆叠空状态。

## 5. 首页

首页是用户打开小程序后的默认工作台，只展示当前农场的少量关键内容。

首页内容顶部只保留日期和基于当前时间的用户问候，随后直接进入核心操作；不增加“今天准备做点什么”等解释性提示。

### 5.1 核心操作

首页优先展示全局生产入口：

```text
开始种养    记农事
记收获      地块管理
```

“记农事”和“记收获”直接进入完整表单，再在表单中选择地块或种养；“地块管理”进入独立地块列表。入口必须保持统一的品牌色、图标容器和触控反馈。

### 5.2 当前农场简要状态

工作台只显示地块数与进行中种养数量，用于确认当前工作上下文；点击进入农场总览。首页不罗列当前种养，避免生产清单挤占高频操作和最近动态。

### 5.3 最近动态

农事、采收、捕捞和出栏统一展示为最近动态，不拆成多个大模块：

```text
今天 14:20
1 号大棚 · 黄瓜
施肥 · 张三

昨天 17:30
东鱼塘 · 鲈鱼
捕捞 35 kg · 李四
```

这里只负责回答“最近发生了什么”，不替代地块历史列表。

首页等全局入口直接打开完整收获表单，再通过表单中的必填种养字段选择具体 Production；选择卡片同时展示地块、种类、品种、开始日期和初始数量。

## 6. 农场 Tab

农场 Tab 代表当前农场的生产总览，先回答规模、利用和当前生产状态，再提供具体管理入口；不在 Tab 首屏逐条罗列全部地块。

### 6.1 农场统计

首屏统一展示：

```text
总面积
地块数
进行中种养数
闲置地块数
```

闲置地块定义为当前没有 ACTIVE Production 的地块。面积使用后端标准化的 `areaM2` 汇总并换算为亩；整数不显示无意义的小数部分。

### 6.2 当前种养

当前 ACTIVE 种养在农场 Tab 展示，列表至少包含种类、品种、地块和开始日期，用于区分同种类的不同种养：

```text
黄瓜 · 水果黄瓜      进行中
1 号大棚 · 8 月 1 日开始 · 17 天
```

### 6.3 地块列表

地块列表是独立二级页面，由首页“地块管理”和农场 Tab“地块列表”进入。页面负责地块创建、摘要列表和进入地块详情：

```text
1 号大棚
大棚 · 6.3 亩
```

项目只维护这一份地块列表实现。种养、农事等表单需要选择地块时，通过同一页面的选择模式进入；选择模式点击地块后把结果返回表单，管理模式点击地块则进入详情。OWNER／ADMIN 在两种模式下都可创建地块，创建后返回同一列表继续操作。不再单独维护 `plots/select` 页面。

页面顶部使用轻量工具栏说明当前模式和可用地块数，创建地块使用弱化的品牌色按钮，避免与列表主任务争夺注意力。地块行统一展示类型图标、名称、类型和面积；面积缺失时仅对缺失字段使用警告色。选择模式复用同一行结构，通过浅绿色背景和勾选图标表达当前选择。

### 6.4 农场 Tab 的管理入口

农场 Tab 提供“地块列表”和“农场设置”入口，但不直接铺开成员列表。成员管理的正式层级仍为：

```text
我的 → 我的农场 → 某个农场 → 成员管理
```

## 7. 地块详情

地块详情是 MVP 最重要的业务页面，是地块基本信息、当前种养、历史种养、农事和收获的聚合中心。

顶部使用一张概览卡集中展示：

```text
果园 · 1 号
10 亩    当前种养 5 项    2026-08-18 创建
```

地图或地块轮廓是可选增强内容，不得阻塞地块创建和生产记录。没有边界数据时仍然显示普通信息卡。

概览卡下方固定集中三个高频操作：

```text
开始种养    记农事    记收获
```

没有 ACTIVE Production 时，“记收获”显示禁用视觉，点击后提示用户当前没有进行中的种养。开始种养和结束种养的具体业务操作仍在对应种养流程中完成。

详情主体按生产工作顺序纵向排列，不使用页面内 Tab：

```text
地块概览
快捷操作
当前种养
历史种养（有数据时）
生产记录
```

### 7.1 种养

当前种养优先展示，列表行必须包含足够的批次识别信息：

```text
黄瓜  [水果黄瓜]                         进行中 >
农业 · 2026-08-01 开始 · 初始 100 株
```

一个地块存在多个 ACTIVE Production 时分别展示，不假设一个地块只能有一条当前种养。种类相同时依靠品种、开始日期和初始数量区分批次。历史种养沿用同一列表行结构，仅将图标、品种和状态弱化。

### 7.2 农事

展示该 Plot 的全部 FarmOperation，包括：

- 关联某个 Production 的农事
- `productionId = null` 的纯地块农事

提供“+ 记农事”入口。

创建农事时，地块是表单中的首个必填项：首页等全局入口直接打开表单，再通过该字段选择地块；从地块详情进入时自动带入当前地块，仍可重选当前农场内其他地块。编辑既有农事时，地块归属不可变更。农事类型使用独立的平铺选择页；关联种养默认“整个地块”，如需追溯批次，使用展示种类、品种、开始日期与初始数量的卡片选择。

操作人和记录人遵循以下规则：

- 操作人默认当前登录用户，但允许选择当前农场的其他有效成员。
- 记录人由后端从 JWT 自动写入，前端不提供编辑入口。
- 如果操作人与记录人相同，可以只展示“操作人”。
- 如果二者不同，同时展示“操作人”和“记录人”。

### 7.3 收获

展示该地块下所有 Production 的 HarvestRecord，并标识其所属种养：

```text
08-17
黄瓜 · 1 号大棚
采收 80 kg
操作人：李四 · 记录人：张三
```

地块详情将农事记录和收获记录合并为“生产记录”入口组，减少重复标题和卡片。顶部“记收获”进入当前地块的收获表单，种养选择范围限制在当前地块；ENDED Production 的收获记录可以查看，但不能编辑或删除。

## 8. 我的 Tab

我的 Tab 负责用户账号和低频农场管理。

页面只展示身份栏和农场入口：

```text
头像  昵称                  设置
      138****8888

我的农场           当前农场名称  >
当前农场管理       当前角色      >
```

身份栏不显示“个人账户”、编辑说明或其他描述文案；右侧设置图标使用不小于 44 px 的点击区域。“关于掌上农场”和“退出登录”不再占用 Tab 页面空间，统一迁移至原生导航的设置页。

设置页使用简单分组列表，不使用头像悬浮、大面积渐变或嵌套卡片：

```text
账号
昵称              当前昵称  >
手机号            138****8888

其他
关于掌上农场                >

退出登录
```

当前 MVP 只允许修改昵称。手机号以无箭头的只读行展示，不提供无效点击入口；注销账号不展示，待数据保留、OWNER 归属等业务规则明确后再实现。退出登录必须二次确认。

### 8.1 我的农场

展示用户加入的全部 Farm：

```text
开心农场
农场主 · 12 个地块
>

生态农场
管理员 · 8 个地块
>

鱼塘基地
成员 · 3 个地块
>

+ 创建农场
```

MVP 暂不提供“加入农场”流程。加入能力需要后续单独设计 farmCode 搜索、申请和审批。

### 8.2 农场管理

从“我的 → 我的农场 → 某个农场”进入，根据 FarmMember 角色展示能力：

| 角色 | 页面能力 |
| --- | --- |
| OWNER | 农场信息、成员管理、农场编号、退出农场 |
| ADMIN | 农场信息、成员管理、退出农场 |
| MEMBER | 农场信息、退出农场 |

删除农场不在 MVP 页面和接口范围内。OWNER 退出仍须遵守“农场至少保留一位 OWNER”的业务规则。

### 8.3 成员管理

成员列表展示昵称和角色，不展示完整手机号：

```text
张三
农场主

李四
管理员

王五
成员
```

权限规则沿用业务文档：ADMIN 不能操作 OWNER，OWNER 至少保留一位；前端按钮状态不能代替后端权限校验。

## 9. 独立业务页面

### 9.1 开始种养

流程：

```text
选择种类 → 填写种养信息 → 提交
```

首页和地块详情的“开始种养”都直接进入同一个种类选择页，不再先选择地块，也不保留额外的开始种养中间页。选择 Species 后进入正式表单，表单按“地块、种类、品种、行业字段”的顺序填写：

- 从首页进入时地块为空，用户必须通过表单首项选择当前农场内的地块。
- 从地块详情进入时默认带入当前 Plot，但仍允许在当前 Farm 内重选。
- 种类在表单中只读展示；需要更换时返回种类选择页。
- 品种是正式表单中的选填字段，不再放在选择种类与表单之间的过渡页面。

提交时以表单当前选中的 `plotId` 创建 Production。根据 Industry 显示对应字段和 Species 的固定个体单位：农业、林业按种植方式动态显示“移栽／播种时间、数量”；牧业显示必填入栏日龄和入栏数量，不显示作业方式；渔业显示必填养殖数量和作业方式。农业的预计亩产固定为“公斤／亩”，农业／林业的株间距固定为“厘米”。

### 9.2 选择种类

Species 使用独立选择页面，不用一个普通 Picker 承载大量选项：

```text
选择种类

[搜索种类]

最近使用
黄瓜  水稻  鲈鱼

农业   林业   牧业   渔业
```

Species 为系统预置数据，前端不提供管理入口。

### 9.3 记录农事

从地块详情进入时自动带入 Plot。Production 选择规则：

| 地块状态 | 默认行为 | 请求中的 `productionId` |
| --- | --- | --- |
| 没有 ACTIVE Production | 整个地块 | `null` |
| 只有一条 ACTIVE Production | 自动选中 | 该 Production ID |
| 多条 ACTIVE Production | 用户选择某次种养或整个地块 | 对应 ID 或 `null` |

表单默认当前时间、当前用户和人工作业方式。操作人可以改选当前农场成员；记录人不由前端传入。

### 9.4 记录收获

从具体 Production 进入时自动带入 Plot、Species 和 Production。首页等全局入口也直接进入完整表单，把种养作为首个必填项；选择页用地块、种类、品种、开始日期和初始数量区分同种类的不同种养。创建时允许更正所选种养，编辑既有记录时种养归属锁定。页面标题根据 Industry 显示“采收”“捕捞”或“出栏”。

核心字段：

```text
数量、作业方式、时间、操作人、产品名称、产品等级、备注
```

默认人工、当前时间和当前登录用户为操作人；操作人允许修改，记录人由后端生成。

数量字段按行业显示：农业“采收重量”、渔业“捕捞重量”、林业“采收数量”、牧业“出栏数量”。表单不提供单位选择器；农业和渔业固定显示公斤，林业和牧业显示 Species 的个体单位。公斤允许小数，个体单位必须为整数。产品名称默认使用种类名称但允许修改，等级不自动填写业务事实。

### 9.5 结束种养

页面保持简单，只填写结束日期并确认：

```text
结束种植

黄瓜
1 号大棚

结束日期
2026-08-17

[确认结束]
```

允许没有任何 HarvestRecord 的 Production 直接结束，不要求重复填写产量、原因或备注。

## 10. 视觉主题基线

### 10.1 设计定位

主题定位为：自然、可靠、轻量、易操作的生产管理工具。

避免过度卡通化、复杂渐变和高饱和装饰，让颜色承担行业状态提示，而不是装饰页面。

### 10.2 颜色 Token

前端使用原始色阶、语义色和组件尺寸三层 Token。关键语义色如下：

```css
:root {
  /* Brand */
  --primary: #286b46;
  --primary-pressed: #1f5638;
  --primary-light: #e8f2eb;
  --primary-subtle: #f2f7f3;

  /* Background */
  --bg-page: #f6f8f5;
  --bg-card: #ffffff;
  --bg-muted: #f0f3ef;

  /* Text */
  --text-primary: #17231b;
  --text-secondary: #536158;
  --text-tertiary: #7f8b82;
  --text-inverse: #ffffff;

  /* Border */
  --border: #dce3dc;
  --divider: #e8ede8;

  /* Danger */
  --danger: #a9433b;
  --danger-light: #f8eae8;

  /* Warning */
  --warning: #8b5a16;
  --warning-light: #f8f0df;

  /* Info */
  --info: #3e6872;
  --info-light: #e7f0f1;
}
```

语义约定：

| Token 组 | 用途 |
| --- | --- |
| `primary` | 主按钮、选中 Tab、主要链接和确认操作 |
| `primary-light` / `primary-subtle` | 选中背景、成功提示、轻量品牌背景 |
| `bg-*` | 页面、卡片和弱化区域背景 |
| `text-*` | 标题、正文、辅助信息和反色文字 |
| `border` / `divider` | 控件边框、卡片边界和内容分隔 |
| `danger` | 错误、移除和危险操作 |
| `warning` | 风险提醒、待处理和非阻断性警告 |
| `info` | 不带操作倾向的说明信息 |

农事、收获、地块和种养都属于同一条生产主流程，其按钮、选择、焦点和可点击卡片统一使用 `primary`，不再用黄色区分收获入口。`warning` 只表示真实风险或待处理状态，`info` 只表示无操作倾向的说明。`text-tertiary` 只用于占位符、禁用态或非关键信息。

### 10.3 组件风格

- 页面背景使用 `--bg-page`，内容卡片使用 `--bg-card`。
- 基础间距遵循 4 px 网格，常用页面间距为 16 px，区块间距为 24 px。
- 卡片圆角以 12 px 为主，强调卡片使用 16 px；控件圆角为 8 px。
- 页面优先使用留白和分隔线建立层级；卡片只承载明确成组的信息，不嵌套无目的边框，阴影只用于确有浮层关系的元素。
- 页面不使用解释页面用途的描述性副文案，优先展示名称、状态、数值和必要的操作反馈。
- 使用线性、圆润、易识别的图标；TabBar 图标保持同一套线宽。
- 主操作使用叶绿色；危险操作使用红色，并要求二次确认。
- 行业差异优先通过文案和图标表达；辅助色不改变交互控件的主品牌色。
- 默认使用系统中文字体，不为 MVP 引入额外字体资源。
- 首版只做浅色主题，不增加暗色模式和复杂动效。
